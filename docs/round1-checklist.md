# Round 1 PDF checklist

Combines the organiser's PDF instructions with the Round 1 items from the problem statement. Tick each off before uploading.

## Required sections (organiser instructions)
- [ ] 1. Understanding of the problem statement
- [ ] 2. Users affected by the problem
- [ ] 3. Proposed solution
- [ ] 4. Complete product workflow
- [ ] 5. Main features we intend to build
- [ ] 6. Technology stack
- [ ] 7. Responsibilities of each team member
- [ ] 8. Development plan across all three rounds
- [ ] 9. Expected impact
- [ ] 10. Future scope after the event
- [ ] 11. Complete team and participant details

## Also asked for in the problem statement (not in the list above)
- [ ] Evidence the problem is real (stats, examples, articles)
- [ ] Research / interviews / observations / surveys
- [ ] Integrations and data sources
- [ ] Responsible design: privacy, security, human oversight, AI disclosure
- [ ] Value proposition
- [ ] "The three improvements" we will deliver (judged in Rounds 2 & 3; confirm with organisers what this refers to)

## Score-driven reminders
- **Understanding (25):** who experiences it, how it hurts them, and *which specific part* we solve.
- **Solution (25):** workflow concrete enough that a judge can picture using it.
- **Technical plan (20):** *why* this stack; name the hardest technical part and how the architecture handles it.
- **Originality (15):** explicitly say what's different from other teams' likely approach.
- **Feasibility (15):** focused scope beats a big idea; show what's in vs. out.

## Before submitting
- [ ] Drive link set to "Anyone with the link → Viewer"
- [ ] Link tested in an incognito window
